# 首版产品梳理

## 产品定位与取舍

把早期线索转为有依据、可筛选、可持续复查的项目档案。用户是内部研究员，而不是自动化交易参与者。两份 PDF 为需求与视觉参考；本次用户要求优先：首版采用人工录入，不把 PDF 中“自动采集、每小时更新”实现成虚假的数据功能。

界面按后续提供的参考图更新为象牙白底、赤金图例和标签、黑 / 橙色文字；中文使用微软雅黑，英文和数字使用 Cambria。保留统计卡、三层项目池与项目表格。仪表盘以实际数据库的研究分层替代没有真实数据源支撑的全网趋势曲线。

## 首版交付范围

| 页面 | 核心能力 |
| --- | --- |
| 仪表盘 | 项目总量、高评级、关注、到期复查、三层研究流程、评级分布、最新项目、事件日程 |
| 三层项目池与归档 | 搜索、多字段筛选、排序、批量移动与关注、CSV 导出 |
| 三步项目录入 | 基础信息 → 六维评分与 KOL 信号 → 跟踪设置；允许只保存基础信息 |
| 项目研究档案 | 全部资料、链接、评分拆解、人工调整依据、关键动态、下一步行动、追踪笔记 |
| 我的跟踪 | 汇总已关注 / 已参与项目，继续筛选、查看和编辑 |
| KOL 名单 | 手工新增、记录领域与参考权重、移除；项目信号引用权重快照 |
| 研究动态 | 录入、修改、分层 / 状态 / 人工评级变化、跟踪笔记、评分权重变更 |
| 评分设置 | 六维权重调整，合计校验与全项目即时重算 |

## 字段分组

- 识别：项目名称（必填）、负责研究员（必填）、X handle、链、赛道、一句话叙事。
- 来源：官网、Mint / 参与链接、发现来源与依据。
- 评分：六维 0–100 分；KOL handle、权重、互动类型；可选人工评级及必填调整原因。
- 行动：项目分层、跟踪状态、事件时间、复查时间、人工分池原因、关键动态摘要、下一步行动。
- 历史：创建 / 更新时间、操作摘要、追加的跟踪记录、手填记录人。

数据库使用 UTC，界面与时间输入使用当前浏览器时区。未填写时间显示“待确认”。未填写评分显示“待评估”，不等同于 0 分。

## 评分与流转

总分为 Σ（维度分 × 权重）/100，显示一位小数。建议权重：重要人员 35%、互动热度 20%、账号质量 15%、叙事内容 15%、时效一致性 10%、辅助信号 5%。

本次把 PDF 的 S 级“附加条件示例”具体化为：分数至少 85，且两个不同的权重 ≥80 KOL 有推广、转发或回复，否则降至 A。A/B/C 按 70/50 阈值划分。A 的“基础质量良好”等描述由研究员评估，不伪装成自动校验。可人工覆盖评级，但须记录原因；原始自动评级仍显示。

分池始终由研究员决定，不因评分变化自动移动。预备参与池必须有事件时间；未到 A 级可通过填写人工原因进入。默认按事件时间先后排序。“忽略”是跟踪状态，“已归档”是分层，两者彼此独立。

## 内测验收建议

1. 新建一个只含基础信息的项目，确认显示“待评估”。
2. 补全评分、添加重要人员互动，查看分数和评级是否符合研究标准。
3. 尝试同名或同 X 账号录入，确认去重提示。
4. 将项目移入观察池，再补全事件时间移入预备参与池。
5. 添加至少两次跟踪记录，刷新和重启后核对资料仍存在。
6. 按链、评级、状态筛选并导出，确认输出范围与列表一致。
7. 调整权重，确认评分变化是否符合团队判断。
